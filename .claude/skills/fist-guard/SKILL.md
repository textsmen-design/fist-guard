# FIST Guard — проверка перед публикацией

FIST Guard — локальный сканер на Python без зависимостей. Он **только читает**: не меняет, не удаляет файлы и ничего не отправляет в сеть. Это демонстрационная версия: история git и персональные данные не проверяются, скажи об этом пользователю, если это важно.

## 1. Найти FIST Guard

По порядку, первое сработавшее:

1. Мы в репозитории FIST Guard (есть `fist_guard/scanner.py`) → `python3 -m fist_guard ...`
2. Установлена команда: `fist-guard --version`.
3. Иначе предложи пользователю (не устанавливай молча):
   `git clone https://github.com/textsmen-design/fist-guard.git ~/fist-guard`
   и запускай `python3 -m fist_guard ...` из `~/fist-guard`.

Если пользователь хочет попробовать без своего проекта: `python3 -m fist_guard demo /tmp/kolosok-demo`.

## 2. Проверить

```bash
python3 -m fist_guard scan <папка> --format json > /tmp/fist-guard-report.json; echo "exit=$?"
```

- `exit=0` — ЗЕЛЁНЫЙ, `1` — ЖЁЛТЫЙ, `2` — КРАСНЫЙ, `3` — ошибка (неверный путь).
- Читай `/tmp/fist-guard-report.json`: `verdict`, `counts`, `findings`, `recommendations`. Значения уже замаскированы.
- Для наглядности предложи: `python3 -m fist_guard ui <папка>` (интерфейс в браузере) или `--html report.html`.

## 3. Объяснить пользователю

Сначала одной фразой вердикт, потом по смыслу:

1. **Критично и уйдёт наружу** (`severity=high`, `exposed=true`): что за ключ, в каком файле, чем опасно.
2. **Проверить вручную** (`medium`): твоя оценка — похоже на настоящий пароль или на тестовое значение. Если нужно, посмотри строку в файле, но не выводи значение.
3. **Закрыто .gitignore** (`exposed=false`): одной строкой, это не уйдёт при публикации.

Говори простыми словами, как для человека, который не программист.

## 4. Предложить исправления — только с согласия

Предложи план и **спроси разрешения** перед каждым изменением:

- ключ в коде → перенести в `.env`, читать через `os.getenv` / `process.env`, добавить `.env` в `.gitignore`, создать `.env.example` без значений;
- `.env` уже в git → `git rm --cached .env` и коммит (файл на диске остаётся);
- **любой ключ, который был в git или мог уйти наружу, → перевыпустить у провайдера.** Исправление файла не отменяет утечку;
- если ключ мог попасть в старые коммиты, предупреди: демо-версия историю не проверяет; ключ надёжнее перевыпустить.

После исправлений запусти проверку снова и покажи новый вердикт.

## Запреты

- Никогда не выводи полное значение секрета: ни в ответе, ни в командах, ни в коммитах.
- Не открывай `.env` и файлы ключей целиком; если нужно, показывай только имена переменных.
- Не удаляй файлы, не переписывай историю git, не делай `git push` без явного согласия.
- При ЗЕЛЁНОМ говори «автоматическая проверка секретов не нашла», а не «секретов нет».

## Работа с репозиторием FIST Guard

- Структура: `fist_guard/rules.py` (правила), `scanner.py`, `masking.py`, `report.py`, `server.py` + `web/index.html`, `demo.py`, `cli.py`.
- Тесты: `python3 -m pytest -q`, должны проходить все.
- Настоящие ключи в тестах запрещены: используй `fake_values()` из `demo.py`.
- Код распространяется на условиях `LICENSE` (все права защищены): не предлагай публиковать изменённые копии.
